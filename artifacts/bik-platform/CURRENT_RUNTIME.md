# التشغيل الحالي — BIK v13

هذه الوثيقة تصف الواجهة المنشورة وأداة التطوير المحلي في `server.ts`، وتعلو في وصف التشغيل على وثائق التصميم القديمة التي تذكر PostgreSQL أو الاحتفاظ ببيانات العملاء. وجود ملفات الترحيل أو مسارات خادم قديمة لا يفعّلها.

## البنية

- تطبيق عربي RTL ضمن `artifacts/bik-platform`. تُنشر واجهة React وVite من `dist` كملفات ثابتة.
- في التطوير المحلي يخدم Express الواجهة وطلبات BIK تحت `/_bik-api`، ويعيد كتابة هذه البادئة إلى `/api` قبل معالجة المسارات. يستخدم الأمران `start` و`serve` الحزمة المبنية في `server-dist/server.js`.
- وضع التخزين `session_only` و`CLIENT_DATA_STORAGE_DISABLED = true`. لا يهيئ التشغيل قاعدة بيانات ولا تخزين ملفات أو CRM لتحليلات BIK. مسارات الإدارة غير مفعلة، ومسارات حفظ الإجابات وتوليد التشخيص على الخادم واستقبال العملاء والأحداث مغلقة.
- يرد مسار بدء الجلسة بمعرّف ورمز مؤقتين دون حفظ سجل زائر. يحتفظ محدد معدل المحادثة بعدادات مؤقتة بحسب عنوان IP في ذاكرة العملية؛ لا يحفظ نصوص المحادثة أو بيانات التشخيص.

## تدفق البيانات والخصوصية

1. تبقى الإجابات وحالة الرحلة في `sessionStorage` عبر المخزن وقائمة التنقية البيضاء. `startMode` قيمة محصورة في `analysis` أو `crisis`، وتُنظف عند البدء من جديد. لا يغيّر اختيار البداية الأسئلة أو الدرجات.
2. يولّد `src/services/diagnose.ts` التقرير في المتصفح بمعادلات وقواعد ثابتة. لا يرسل إجابات التشخيص إلى خادم BIK أو نموذج خارجي. صفحات المراجعة وحاسبة تغطية الكلفة تعملان محلياً أيضاً؛ إيراد الحاسبة حالة مكوّن فقط لا يُحفظ أو يُرسل.
3. تبقى بيانات الاسم والمنشأة والهاتف في المتصفح، وتُضاف إلى رسالة واتساب التي يختار الزائر إرسالها. استقبالها في خادم التطبيق معطل.
4. يحذف التطبيق مفاتيح BIK القديمة من `localStorage` عند البدء ولا يحفظ فيه نسخة استرداد. يبقى التقرير وتقدّم المشاركة في تخزين التبويب أثناء الجلسة. تُحدَّد اللهجة من `intakeAnswers.country` دون اختيار مستقل في الصفحات.
5. تفتح المشاركة جزءاً جاهزاً إلى واتساب، ثم يرسله الزائر بنفسه ويؤكد الإرسال. الإقرار تصريح من الزائر، وليس إشعار استلام من واتساب أو المستشار. لا يرسل الخادم الرسالة.
6. عند اختبار معالج المحادثة محلياً، يستقبل سجل الرسائل المنقح والقطاع وحالات المحاور و`mode` الاختياري ومؤشري `overallComputed` و`lossSustainsExecutive`. لا تُرفق حقول هوية أو بلد أو مدينة أو إجابات أو مبالغ. يرفض التحقق قيمة `mode` غير المسموحة، ويحذف الحقول الزائدة.
7. يصل إلى مزود المحادثة نص `buildChatSystemPrompt` وسجل الرسائل المنقح. يحتوي النص على القطاع والمحاور وحالة احتساب النتيجة والعرض المرشح. يؤثر `mode` ومؤشر الخسارة في اختيار العرض، ولا يُسلسلان إلى المزود كحقول مستقلة أو كائن سياق خام. لم يتغير نص دالة النظام في المهمة 5. التنقيح الآلي للنص الحر ليس كاشفاً مضموناً لكل بيانات شخصية.
8. تُخدم ملفات Noto Sans Arabic وNoto Naskh Arabic من أصل التطبيق ضمن `dist/assets` مع `font-display: swap`، دون طلب خطوط من Google.

لا تكتب مسارات التطبيق النشطة إجابات أو تقارير أو محتوى رسائل إلى سجل أو قاعدة بيانات. هذه الجملة لا تصف إعدادات سجلات الوكيل أو المضيف خارج الكود. الاختبارات ولقطات التسليم تستعمل بيانات اصطناعية.

## التشغيل والتحقق

من جذر مساحة العمل، باستخدام Node.js وpnpm المتوافقين مع الاعتماديات:

```bash
pnpm install --frozen-lockfile
pnpm --filter @workspace/bik-platform run dev
pnpm --filter @workspace/bik-platform run typecheck
pnpm --filter @workspace/bik-platform run build
pnpm --filter @workspace/bik-platform run test
```

يحتاج اختبار الخطوط إلى مخرج بناء قائم، لذا يسبق البناء الاختبار عند إعداد مساحة نظيفة. المنفذ الافتراضي 3000 ويضبطه `PORT`. لا يحتاج التشخيص إلى `DATABASE_URL` أو مزود نموذج. المحادثة وحدها تحتاج `OPENROUTER_API_KEY` على الخادم؛ عدم توفره ينتج خطأ توفر صريحاً. وضع `BIK_CHAT_MOCK=1` للاختبار خارج الإنتاج فقط.

## حدود الإثبات

- تثبت الاختبارات القواعد والسيناريوهات الاصطناعية التي تشغّلها.
- يثبت اعتراض رابط واتساب الوجهة والنص وحالة الواجهة، ولا يثبت إرسالاً أو استلاماً.
- تثبت لقطة الشاشة المظهر في المقاس والمسار المصورين.
- لا يعني إنشاء أرشيف الإصدار نشره أو إعداد مزود محادثة أو إرسال رسالة حقيقية.
